# 界面底线

不管选哪种风格都要守的规则。写 `docs/设计规范.md` 时逐条过一遍：满足的照写进规范；做不到或不想做的，在规范里写明例外和理由，并经产品负责人同意。

这份清单只管"不出错"，不管"好不好看"。好不好看由产品负责人选的风格方向决定（见 [风格方向样例.md](风格方向样例.md)）。

数值按网页 / 桌面的 px 写。小程序用 rpx 时按 1px ≈ 2rpx 换算（以 750rpx 宽为准）。

## 1. 文字

- 阅读用的正文不小于 16px（小程序 32rpx），列表、表单里的界面文字不小于 14px，最小 12px，只用于日期、角标这类辅助信息
- 行高：成段的中文正文 1.6–1.8，单行的界面文字 1.4–1.5
- 一行不要太长：成段正文的区域最宽 680–720px，大约每行 35–45 个汉字
- 字号分级：每一级至少是下一级的 1.2 倍。级数尽量少，一般 4–5 级（大标题、标题、正文、辅助、最小）
- 字重最多两种（常规 + 中粗或半粗）。不用细体写小字，不整段加粗
- 中文用系统字体：苹方（PingFang SC）、微软雅黑（Microsoft YaHei）、Windows 11 上的 Segoe UI Variable，小程序用默认字体。想要特色，最多再加一个英文或数字字体

## 2. 颜色

- 只有一个主色。界面绝大部分是中性色（白、灰、黑），主色只出现在主按钮、选中状态、链接和焦点上
- 状态色（成功、警告、错误）单独定，不和主色混用
- 对比度：正文至少 7:1，次要文字至少 4.5:1，24px 以上的大字以及图标、输入框边框至少 3:1。"浅灰底上的浅灰字"最常见，一定要查
- 颜色不能是唯一的信息：出错时除了变红，还要有文字或图标
- 要做深色模式的，单独给每个颜色的深色值，不能简单反色

## 3. 间距和版式

- 间距用 4 的倍数：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64
- 同一层级的元素间距一致，页面左右边距一致（手机一般 16–24px）
- 同一行的卡片一样高，内边距一样

## 4. 圆角和层次

- 圆角分 2–4 档（例如小 / 中 / 大），按元素大小选，全产品统一
- 一个圆角容器里面再放圆角元素时，内圆角 ≈ 外圆角 − 两者之间的间距，内外弧线才平行
- 区分区域选一种主要手段：底色深浅、1px 细线、或轻阴影。不要三种叠在一起；阴影要轻，静止时宁可不用

## 5. 组件

- 每屏只有一个主按钮（实心主色）。按钮样式最多两种（主、次），另加文字链接
- 卡片里不再套卡片，盒子最多嵌套两层，不要"盒子里的盒子里放字"
- 同类东西长得一样：同一种卡片、同一套图标（线性和面性不混用）
- 新页面先找现有组件复用，没有合适的再新做，新做的补进设计规范

## 6. 触控和表单

- 可点区域至少 44×44px（小程序 88rpx），哪怕图标本身更小；相邻两个可点元素至少隔 8px
- 输入框高至少 44px，输入的字不小于 16px（避免 iPhone 上自动放大）
- 底部固定的操作栏要给手机底部安全区留位置（`env(safe-area-inset-bottom)`）
- 字段名写在输入框上方或左侧，不能只靠框里的占位提示
- 提交时才校验；错误写在对应字段下方，光标跳到第一个出错的字段
- 按钮写清动作："保存修改""提交订单"，不写"确定""好的"；提交中的按钮置灰，防止连点

## 7. 页面状态

每个列表、每个要加载数据的页面，都要设计好这几种状态的样子：

- 加载中（骨架屏或进度提示，不让页面空白闪一下）
- 空状态（告诉用户为什么是空的、下一步能做什么，最好给一个按钮）
- 出错（说清楚出了什么问题、能不能重试）
- 内容很多或很长时（长标题、长名字、上千条数据）不撑破、不重叠

## 8. 动效

- 动效只用来说明"东西从哪来、到哪去"或"刚刚发生了什么"，不为了热闹
- 时长：点击、悬停反馈 100–200ms，面板和弹窗 200–300ms，页面切换一般不超过 400ms。更长的特色动效（比如 Paperwind 的粒子翻页）要在设计规范里单独写明
- 只动位置、缩放、透明度，不动宽高和边距（会卡顿、会让页面跳）
- 动效播放时不挡操作：照样能点、能滚；连续触发时上一段立刻结束
- 用户在系统里开了"减少动态效果"时，位移动画改成淡入淡出或直接变化，内容不能因此藏着不出来
- 网页和桌面端：用键盘操作时焦点框始终看得见

## 9. 去掉"AI 味"

AI 做界面最常见的毛病，看到就改：

- 每个区块都在滚动时淡入、滑入
- 轮播图、自动切换的标签页、到处闪烁的小圆点
- 当装饰用的紫蓝渐变、发光、层层叠叠的毛玻璃
- 界面里用 emoji 代替图标
- 编造的数据、用户评价、用户名和头像（演示数据要在验收版本里明确标出，正式版不能出现）
- 占位文字留在界面上："示例""敬请期待""Lorem ipsum""[待补充]"
- 空话："赋能""一站式""极致体验""无缝衔接"。标题直接说这是什么，按钮写"动词 + 对象"

## 出处

第 1–6、8、9 节有一部分参考了 taste-skill（github.com/Leonxlnx/taste-skill，MIT 许可）里的 system、motion、cards、copy-voice 规则，按中文排版、小程序和应用界面做了调整。它针对官网落地页的结构规则，以及作者的个人偏好（不许用紫色、不许用常见字体、不许回弹、深色只给科技类），这里都没有采用。
