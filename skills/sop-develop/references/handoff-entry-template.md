# 交接条目模板

加在 `docs/交接文档.md` "变更记录"一节的最上面。

```markdown
### KF-YYYYMMDD-NN · 一句话标题

- 日期：YYYY-MM-DD
- 改动人：人名 / AI（模型名）
- 起因：产品负责人的原话，或对应的验收编号（如 YS-20261103-01-Q1）
- 改了什么：
    - <文件>：<改了什么>
    - <文件>：<改了什么>
- 测试：N 项通过（原 M 项）；新增「……」；修改「……」（行为改了，不是放宽）
- 实际验证：<环境和尺寸>下走了：<流程 1>；<流程 2>。验证完已恢复演示数据
- 版本：<改动前> → <改动后>
- 验收清单：新增 x.x–x.x；修改 x.x（KF 修改）；或「无变化（只改了样式，没有改变任何条目的预期结果）」
- 验收原则：无变化（不需要新环境和账号；问题都能用现有四级定义覆盖）
- 其他文档：README / 部署说明 / PRD 改了什么
- 建议复验：x.x、x.x，及所在小节；或「全量验收（改了数据结构）」
- 遗留问题：<没做完的；需要产品负责人决定的；需要产品负责人在真机上看的>
```

## 小改动的写法

不改规则、数据结构、接口和用户流程的改动，写一条短的，当天的接着往里加：

```markdown
### KF-YYYYMMDD-NN · 小改动：按钮文案和间距
- 改了什么：pages/post/new.vue「提交」改成「发布」
- 测试：57 项通过
- 改了什么：components/PostCard.vue 卡片间距 12 → 16；测试：57 项通过
```

## 写好的例子（问问 KF-20261103-01 节选）

- 起因：用户说「先做转发到群」；又提出「同一个商品大家的标题会一样，再加一个标题填写栏吧」，并选定标题必填 4–30 字
- 测试：57 项（原 54）；新增「帖子标题：必填，4–30 个字」「旧帖子启动时用商品名补上标题」「转发卡片用帖子标题」3 项。临时去掉标题校验，「帖子标题」那项失败，改回后通过
- 实际验证：恢复演示数据后，375×812 下：首页卡片大字是标题；写 3 个字的标题点发布 → 红字「标题要 4–30 个字」；改成 15 个字 → 进新帖详情，顶部是这个标题
- 建议复验：全量验收（改了数据结构和核心规则）
- 遗留问题：转发卡片、从群里点进来的表现要产品负责人在手机上看
